## 一、P0 致命（交付物不可用 / 无回滚保护）

### 1.1 spa.html 交付物已损坏，双击无法运行

已实证的客观事实（非推测）：

| 检查项 | 结果 |
|---|---|
| `createRoot`（React 应用入口） | 0 次出现 |
| `id="root"`（挂载点） | 0 次出现 |
| `<body>` 标签 | 0 次出现 |
| `luckysheet.umd`（表格引擎） | 0 次出现 |
| 文件尾部 | 自约 524KB 起，至文件尾共约 2.45MB（占 82%）为高熵二进制乱码（55.9 万个 U+FFFD 替换字符） |

即：当前 spa.html 里既没有 React 应用，也没有 Luckysheet 引擎，README 承诺的"可离线双击打开"实际必然白屏。根目录与 dist-spa 两份副本损坏起点完全一致，说明产物生成时即已损坏。

**根因（已定位到代码缺陷）**：`scripts/rename-spa.mjs` L30/L44 使用**字符串**作为 `String.replace` 的替换参数：

```js
html = html.replace(regex, `<script ...>${jsContent}</script>`);  // L44
```

替换串中的 `$&`、`` $` ``、`$'` 是特殊序列会被展开。`public/luckysheet/plugins/js/plugin.js`（jQuery）源码中存在 6 处字面 `$&`，展开后会向内联内容注入完整的原始 `<script src="./luckysheet/plugins/js/plugin.js"></script>` 标签（spa.html 内已实测发现 4 处此类注入），注入的 `</script>` 会使 HTML 解析器提前截断脚本块。且脚本 L57 **无任何产物校验**即打印"✅ 成功生成 100% 完整自包含单文件 SPA"。

**修复方向**：改用替换函数 `html.replace(regex, () => literalReplacement)` 使内容按字面处理；生成后增加断言（createRoot / luckysheet.umd / 无 U+FFFD / 标签配对）再报成功；重新构建。二进制乱码尾部的确切成因需在修复后重建时复核。

## 二、P1 高危（违反 AGENTS.md 硬约束 / 功能性缺陷）

### 2.1 "单元格编辑 → 持久化"双向同步链路整体不存在

AGENTS.md §2 要求"前端 Luckysheet 单元格变动实时触发钩子，同步更新 React 内存状态及持久化存储"。实际情况：

- `LuckysheetGrid` 定义了 `onSave` / `onCellUpdated` 两个 props（L27-28）并正确转发了 `cellUpdated` 钩子（L158-163）——**但全项目没有任何一个调用方传入这两个 props**（grep 零命中）。
- 抽查 OpexBudgetWorkbench（L41）、CapexBudgetWorkbench（L155）、HardSoftRevenueWorkbench（L127）、BudgetTable（L32）、StockOrderTable（L26）：全部只传 `sheets`。用户在表内的编辑仅存在于 Luckysheet 内部状态，**切换页签组件卸载即丢失**。
- 连带效应：App.tsx 向各工作台传入的 `onUpdateItems` 等 10+ 个回调全是死 props（接口声明了但组件解构时丢弃），如 OpexBudgetWorkbench L6-10 声明、L12-15 丢弃；CapexBudgetWorkbench 一次丢弃 5 个。
- 全项目唯一真实落库的通道是 BudgetRowModal 弹窗 → Dexie（仅覆盖 3 张表），与 Luckysheet 编辑无关。

**修复方向**（二选一，勿维持现状）：为工作台真正接上 `onCellUpdated` → 适配器反向映射 → Dexie；或砍掉"保存数据"按钮避免误导演示观感。

### 2.2 LuckysheetSpreadsheetWorkbench：违规 + 三处实 bug

该文件是全项目唯一实现了编辑回写的地方，但问题最集中：

- **违反硬约束**：L377 直接调用 `window.luckysheet.create(options)`，AGENTS.md 明令"严禁在业务工作台组件中直接调用，必须通过 LuckysheetGrid"。
- **行映射 off-by-one**：数据行从 r=1 开始（L117 注释自证 `// Data starts at Row 1`），但 L328 `const itemIdx = r - 2` → 第 1 数据行的编辑算出 itemIdx=-1 被静默丢弃，第 2 行写入第 1 条数据，**所有行错位一行**。
- **假保存**：L400-409 `handleSaveLuckysheetData` 调 `getAllSheets()` 后**丢弃返回值**，直接弹"✅ 电子表格数据已成功实时同步保存！"。
- **入口隐蔽**：该页无左侧导航菜单项，只能从 DemoArchitectureModal 跳入——唯一有编辑回写的页面几乎不可达。
- 附带：每次单元格编辑 → state 变更 → destroy+recreate 全表（L385-397 依赖链），编辑时焦点丢失。

### 2.3 LuckysheetGrid 导入 Excel 路径漏做容器清空

主渲染路径正确执行了 destroy + `containerEl.innerHTML = ''`（L83-90），但**导入 Excel 路径**（L313-326）destroy 后直接 create，未清空容器——这正是 AGENTS.md 要防的"幽灵页签"场景，导入文件后页签会叠加。修复：该路径复用 `renderLuckysheet` 的清理逻辑，并补齐 zIndex 等缺失的 options。

### 2.4 静态表格违规（两处实锤）

- **MultiDimPivotWorkbench.tsx**：作为"预算多维明细宽表与交叉透视分析**工作台**"，完全未用 Luckysheet——L444-450（透视矩阵）、L458-464（明细清单）用 ui 库静态 Table 渲染，L442 在表外挂"聚合总计: ¥…万元"摘要条。同时违反硬约束 1（表格必须 Luckysheet）与硬约束 2（禁止外挂统计条）。时间列"1月~12月"为单行表头、"全年总计(万)"未按时间组打头，亦违反 Rule 0.2。
- **DemoExporterModal.tsx**：弹窗内实时预览堆砌 KPI 卡片（L121-138"新签销售预算总额/存量订单未收收入/股权投资年度预算/预算立项与项目总数"，L347-360 又一组），月度分布表为静态 `<table>` 且**"年度合计"列排在 1~12 月之后**（L151），与"全年合计打头"规范完全相反。生成离线报告作为交付文档尚可辩护，弹窗内预览无法开脱。

（灰色地带：RequirementSpecView / TableSpecDrawerModal / SampleTableRenderer / BudgetDataFlowDiagram 中的静态表格属需求文档示意与图例，建议在 AGENTS.md 增加文档示意表格豁免条款，或改造为只读 Luckysheet 快照，一劳永逸消除争议。）

规范 Rule 0.2 要求时间序列表一律两行制（行0 时间大类、全年合计打头跨列合并；行1 指标明细项）。以下适配器为单行平铺，未达标：

## 三、P2 中危（工程质量 / 误导性设计）

### 3.1 假 lint + 全管线零类型检查

- `package.json` L13 `"lint": "tsx -e \"console.log('Lint passed')\""` ——无条件打印"Lint passed"，无任何检查；
- 无 eslint/prettier 配置文件；tsconfig.json 未开 `strict`、无 `noUnusedLocals/noUnusedParameters`；
- build 走 vite（esbuild 转译不查类型），无任何 `tsc --noEmit` 环节。

**这是 2.1 节"死 props 不报错"的直接根因**：若开 noUnusedParameters，CapexBudgetWorkbench 丢弃 5 个 props 会在编译期暴露。建议：`tsc --noEmit` 挂进 build 脚本，strict 渐进开启。

### 3.2 后端 SQLite 层约 1450 行孤儿代码（"架构展品"）

`server/sqliteDb.ts`（657 行）+ `server/sqliteRepository.ts`（800 行）在仓库内零调用方：server.ts 不 import 它们，esbuild 只打包 server.ts；项目根不存在其运行必需的 `data/` 目录——铁证：**这段代码从未执行过**。所谓"本地轻量后端"实际只是个静态文件服务器（无任何 API 端点，前端 grep fetch/axios 零命中）。讽刺的是，这份 repository 恰好写好了前端 Dexie 层缺失的 16 张表完整 CRUD。

内含两处 latent 风险：`executeRawSql`（sqliteDb.ts L584-657）对非 SELECT 语句直接 `db.run()` 落盘、无白名单无参数化——一旦将来被挂到路由即是无鉴权任意 DDL/DML；`LIMIT ${limit}` 字符串拼接（sqliteRepository.ts L674）同理。**建议：删除或接线，二选一，别留引信。**

### 3.3 持久化失败 100% 静默

dbApi.ts 全部 15 个导出函数 catch 后 `console.warn` 返回 `null/false`，App.tsx 调用侧从不检查返回值（L391-451 的 `.catch` 几乎永不触发）。用户在隐私模式等存储不可用场景下毫无感知，静默回退 mock。另：整套 API 命名伪装成 SQLite（`SqliteDbStatus`、`saveBudgetItemToDb`），实为 Dexie/IndexedDB——命名误导后来者。

### 3.4 server.ts 监听 0.0.0.0

L43 `app.listen(PORT, '0.0.0.0')` 把 dev server（含 Vite 中间件）暴露给整个局域网且无鉴权。演示定位建议改 `127.0.0.1`。所幸当前无任何 API 端点，无 SQL 注入/路径遍历暴露面。

### 3.5 App.tsx otherRevenue 视图双重渲染

L790 与 L954 存在两个完全相同的 `{activeTab === 'otherRevenue' && (...)}` 块，各自渲染一个 `<OtherRevenueBudgetWorkbench>`。该页签激活时两个实例纵向堆叠、双份渲染。删除其一即可。

### 3.6 dbApi 约 300 行死代码（含 eval 面）

`executeSqlInDb`（L191-417，含 `new Function('db', ...)` 任意 JS 执行面）、`fetchDbStatus`（文件大小按 `totalRecords*1024` 伪造估算）、`fetchDbAuditLogs`、`resetSqliteDatabase`、股权投资 3 个写入函数（后果：**股权投资数据只能读不能写**）——全部零调用。
