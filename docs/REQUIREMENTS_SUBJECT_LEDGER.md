# 需求规格：软硬销售收入 → 预算科目余额表 → 三大财报 联动链路

> 版本: 1.0  |  日期: 2026-08-31  |  状态: 待实现
> 来源: 用户需求「软硬件销售收入需要转成 预算科目余额表，然后进一步转成 三大财报，3点左至右设计并实现该功能」+「并从 qa、财务专家等多个角度进行验证」

## 1. 目标

打通 **BB.1.3 软硬件销售收入预算表**的三口径月度数据（销售收入 / 预收款 / 验收回款）到**预算科目余额表**，
再由科目余额表按统一预算科目体系（PL/BS/CF）汇总生成**三大财报**（资产负债表 / 利润表 / 现金流量表），
实现"从左至右"的数据流向演示与勾稽验证。

## 2. 数据链路（左至右）

```
[BB.1.3 软硬销售收入表]
  每合同行 × 12月 × 3口径: months(收入) / monthlyPrepayment(预收) / monthlyCollection(回款)
        │
        ▼ 业务事件分录引擎 (subjectLedgerEngine.ts)
  按月生成预算分录（借贷双方金额，万元）:
   ① 收入确认   借:BS0102应收账款+新增   贷:PL01营业收入         [按产品类别(财)→PL0101/0102/0103]
   ② 收预收款   借:BS0101货币资金+       贷:BS0303合同负债
   ③ 验收回款   借:BS0101货币资金+       贷:BS0102应收账款
        │
        ▼ 科目汇总
[BO.x 预算科目余额表] (新工作台)
  逐科目 × 12月: 借方发生 / 贷方发生 / 期末余额
        │
        ▼ 报表取数
[BO.1 三大财报] (复用/增强既有 FinancialStatementsView)
  利润表:      营业收入 = PL01 贷方合计 (全年自 BB.1.3 months 汇总)
  资产负债表:  应收账款BS0102期末 = 期初+借方-贷方 (新增应收-回款)
              合同负债BS0303期末 = 期初+预收-结转
              货币资金BS0101期末 = 期初+预收+回款
  现金流量表:  销售商品收到现金 = 预收+验收回款 (CF0101)
              期末现金 = 期初现金 + 净增加
```

## 3. 规则约定（会计口径）

### 3.1 科目映射（产品类别(财) → PL 明细科目）
| productCategory (AB.3 字典值) | PL 明细科目 |
|---|---|
| 整机台+验收款 | PL0101 主营业务收入-硬件销售 |
| 关键模组+验收款 | PL0101 |
| 零部件耗材+交付款 | PL0101 |
| 软件授权+授权款 | PL0102 软件销售 |
| 技术服务维保+服务款 | PL0103 技术服务与维保运营 |

### 3.2 分录规则（简化借贷演示口径）
| 业务事件 | 借方 | 贷方 | 金额来源 | 备注 |
|---|---|---|---|---|
| 收入确认(月m) | BS0102 应收账款 | PL01xx 营业收入 | `months.m{m}` | 时点法当月全额确认；直线法按月直线 |
| 收预收款(月m) | BS0101 货币资金 | BS0303 合同负债 | `monthlyPrepayment.m{m}` | 若 monthlyPrepayment 缺省，跳过 |
| 验收回款(月m) | BS0101 货币资金 | BS0102 应收账款 | `monthlyCollection.m{m}` | 若回款冲减应收后仍有余，超过部分转贷 BS0303 合同负债（超收预警，可负数留待下年） |

### 3.3 余额递推
```
期末余额[m] = 期末余额[m-1] + 借方[m] - 贷方[m]   (资产类)
期末余额[m] = 期末余额[m-1] + 贷方[m] - 借方[m]   (负债/权益类)
期末余额[m] = 贷方累计 - 借方累计                  (损益类, 年末结转前)
```
*期初余额：BS0102 应收 6,500 万、BS0303 合同负债 2,000 万、BS0101 货币资金 8,500 万（与现行三表期初一致）*

### 3.4 三表勾稽（验收面板显示）
1. **利润表营业收入** = BB.1.3 `months` 全年合计（分产品类别(财)可见明细）
2. **资产负债表平衡**：资产 = 负债 + 权益
3. **现金勾稽**：BS0101 期末货币资金 = 现金流期末现金
4. **净利确认**：FF 验证链条仅覆盖软硬件收入业务（成本费用等仍用既有测算），差异透明展示

## 4. 功能规格

### 4.1 新建文件
- `src/utils/subjectLedgerEngine.ts` — 分录生成 + 科目余额汇总引擎（纯函数）
  - `generateBudgetEntries(items: HardSoftSalesRevenueItem[]): BudgetLedgerEntry[]`
  - `buildSubjectBalances(entries): SubjectBalanceRow[]`（含月度借/贷/余额 + 方向）
- `src/components/SubjectLedgerWorkbench.tsx` — 科目余额表工作台（Luckysheet）
  - 列：科目编码/科目名称/方向/期初余额/1-12月(借方、贷方两列嵌套或单月双列)/期末余额/全年借方合计/全年贷方合计
  - 数据：由引擎从当前 `hardSoftItems` 实时计算（非静态）

### 4.2 修改文件
- `src/types.ts` — 新增 `BudgetLedgerEntry`（月份/凭证摘要/借方科目/贷方科目/金额/来源行id）、`SubjectBalanceRow`（科目/月度借贷余额）
- `src/utils/luckysheetAdapters.ts` — 新增 `buildSubjectLedgerSheet`（列入统一表头规范）
- `src/components/LeftTreeSidebar.tsx` — BO 组挂「BO.3.1 预算科目余额表」节点
- `src/App.tsx` — 新 activeTab `subjectLedger`，渲染工作台，传入 hardSoftItems
- `src/components/FinancialStatementsView.tsx` — 三表增加「软硬件链路」数据源开关（系数推算 ↔ BB.1.3 真实链路），链路模式下营业收入/应收/合同负债/货币资金相关行取自科目余额表

## 5. 验证方案（QA + 财务专家 双视角，含界内自检）

### 5.1 财务专家检查点
- [ ] 分录平衡：每月总借方 = 总贷方（分录级）
- [ ] BS0102 期末应收 = 期初 6,500 + 收入确认 - 验收回款
- [ ] BS0303 期末合同负债 = 期初 2,000 + 预收 - (回款超出应收部分)
- [ ] BS0101 货币资金变动 = 预收 + 回款（本期现金净流入）
- [ ] 利润表营业收入（链路模式）= BB.1.3 全年确认收入合计
- [ ] 三表勾稽面板 4 项指标全部通过（容差 <0.1万元）

### 5.2 QA 检查点
- [ ] `npx tsc --noEmit` 0 错误
- [ ] dev server 200，页面可打开 BO.3.1，Luckysheet 正常渲染
- [ ] 修改 BB.1.3 任意行月度数据 → 科目余额表实时联动更新（同一渲染周期）
- [ ] 删除某合同行 → 合同分录消失，余额重算
- [ ] 三口径任一字段缺省（monthlyPrepayment 未填）→ 引擎稳定，不产生 NaN

### 5.3 负向/边界场景
- [ ] 回款 > 累计应收（超收）→ 超出部分自动转合同负债，不出现负应收（期末BS0102 ≥ 0 或展示预警）
- [ ] 所有行 amounts=0 → 空余额表稳定渲染
- 期初应收 6,500 存在但本期无回款 → 余额按期初递推
