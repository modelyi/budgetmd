# UEADEMO 必要业务需求总结

> 本文档用于记录演示系统必须体现的业务需求边界。系统定位为预算编制演示与需求说明 SPA；内容以预算编制、业务数据联动和财务结果勾稽为核心，不扩展为生产级主数据平台或完整 ERP。

## 1. 系统定位与边界

- 面向制造与科技型集团的全面预算编制演示。
- 覆盖预算编制、汇总分析、财务三表和勾稽检查的完整演示链路。
- 采用单机 SPA 和内置演示数据，不建立独立的客商主数据库。
- 业务表和工作台以 Luckysheet 为主体，支持月度录入、公式计算、下拉选择和 Excel 导出。
- 只保留满足预算编制所需的字段和规则，不引入非必要的复杂业务建模。

## 2. 必要业务需求

### 2.1 预算基础主数据

- **预算年度与期间**：维护预算年度、期间日历及期间控制。
- **组织与法人架构**：维护集团、子公司及孙公司层级，支持单体和集团合并口径。
- **预算科目**：维护利润表、资产负债表、现金流量表及内部交易所需科目。
- **客户与 客户产线**：客户主数据和 客户产线 主数据分开维护，均归入 AA 主数据目录；客户产线 通过客户编码归属客户，供应商不关联 客户产线。
- **项目与预算产品**：维护项目、产品编码、产品名称、规格型号、产品类别(财)和计量单位，供预算表下拉引用。
- **产品类别(财)**：系统统一使用“产品类别(财)”这一名称，不再并列使用“产品大类”或未加限定的“产品类别”。
- **经营假设**：维护预算编制需要的税率、汇率、利率和人力等基础参数。

### 2.2 业务预算编制

- **合同签约额预算**：一合同一行，支持合同性质、合同类型、客户、客户产线、产品类别(财)及 1—12 月签约额拆分。
- **合同类型**：仅保留销售、技术服务、部件销售、软件授权、研发定制五类；不设置设备租赁业务类型。
- **存量在手订单**：维护期初订单状态、已确认收入、已回款及订未收，并测算预算年度收入和成本结转。
- **软硬件销售收入**：按产品数量、单价、交付/验收节奏和回款计划编制收入预算。
- **技术服务收入与料工费**：按服务收入、标准工时、人工费率和物料消耗测算成本与毛利。
- **生产制造预算**：按产品和月份编制排产、材料消耗、制造费用和折旧预算。
- **资本化预算**：按下单、验收、付款、转固和折旧节点编制固定资产采购预算。
- **期间费用预算**：覆盖销售费用、管理费用、研发费用和财务费用。
- **资金与税金预算**：编制资金流入流出、税费、融资和现金余额预测。
- **关联交易与投资预算**：支持内部交易、抵销、股权投资出资及分红等预算事项。

### 2.3 结果汇总与财务勾稽

- 按客户、区域、项目、产品类别(财)、法人主体和业务线进行预算汇总分析。
- 业务预算结果形成收入、成本、费用、资金和税金等汇总结果。
- 自动生成资产负债表、利润表和现金流量表演示结果。
- 校验资产 = 负债 + 权益、期末现金与现金流量表一致、利润结转和借贷平衡。
- 集团合并口径对内部交易进行抵销，并支持查看抵销规则和结果。

## 3. 统一表样

- **编制引擎**：所有编制表、工作台和结果展示表统一采用 Luckysheet；表头位于第 0 行，数据从第 1 行开始，工作表页签承载表名，不设置表内合并大标题。
- **明细表样**：采用“业务维度列 + 预算属性列 + 1—12 月列 + 年度合计/远期预算列”；合同、订单、产品、服务、采购和费用事项按明细行记录。
- **统一展示约束**：所有 Luckysheet 表不展示“序号”列，不展示底部合计/小计/平均/汇总行；`seq` 仅允许作为内部兼容字段保留，不能录入或显示。全年合计列、月度列及其公式必须保留。
- **主数据表样**：采用“编码 + 名称 + 归属组织/关联维度 + 状态”；客户与 客户产线 分开维护，客户产线 通过客户编码关联客户。
- **服务表样**：采用“服务收入主表 + 工时明细附表 + 物料明细附表”三层结构。
- **财务表样**：按利润表、资产负债表、现金流量表三个工作表展示，另提供科目余额和勾稽检查结果。

## 4. 统一表规则

- **填报粒度**：一条合同、订单、销售产品、服务项目、采购事项或费用事项占一行；同一合同原则上不重复拆行，月度拆分放在同一行的 m1—m12 字段中。
- **期间规则**：预算年度使用 1—12 月；年度合计等于月度金额合计；超出预算年度的金额进入下年、后年或以后期间字段。
- **维度规则**：组织、科目、客户、客户产线、项目、产品类别(财)、合同等字段优先使用下拉或自动带出；客户产线 只能从所选客户的可用产线中选择。
- **计算规则**：数量 × 单价形成金额；签约金额 − 已确认收入形成订未收；签约金额 − 已回款形成未回款；收入 − 成本形成毛利；月度及年度合计使用公式。
- **联动规则**：产品类别(财)推荐收入确认方式和成本率；合同主数据带出客户、客户产线、组织等默认值；来源主数据变更后，相关预算表按映射规则重算。
- **校验规则**：必填维度完整、金额字段为数值、月度合计与年度合计一致、内部交易具备交易双方及抵销口径、财务三表满足资产负债平衡和现金勾稽。

## 5. 关键数据关系

```text
客户 1 ─── N 客户产线

合同
 ├─ 客户 → 可用 客户产线
 ├─ 产品类别(财) → 收入确认方式
 └─ 月度金额 → 收入、成本、回款及资金结果

业务预算
 └─ 汇总/映射/勾稽 → 财务三表
```

## 6. 非目标范围

- 不建立独立的客商主数据库。
- 不重复维护独立客户字典。
- 不将 客户产线 作为供应商属性维护。
- 不增加设备租赁合同类型。
- 不增加合同模式、结算模式、履约义务等非必要字段。
- 不把演示系统扩展为生产级审批、权限、数据库和复杂工作流平台。

## 7. 需求说明映射

本总结在系统的“需求说明”模式中作为“0. 核心业务需求总览”展示；各具体业务模块继续在需求说明中分别记录字段、规则、数据流向和演示入口。本文档与 `docs/REQUIREMENTS.md` 配套使用：本文件记录必要业务范围、统一表样和统一表规则，后者记录模块级规格。
