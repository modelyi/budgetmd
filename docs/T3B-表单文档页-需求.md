# T3B 页签替换：表单文档页（需求与边界）

> 需求来源：用户指令「T3A T3B 按照要求改为 markdown 文件」
> 记录时间：2026-10-10
> 承接与替代：本条承接并替代 `docs/T3A-表单文档页-需求.md` §5 中「不改 T3B（`budget-multi`）页签」的边界；T3A 页签自身不受影响，其页面与 37 篇文档保持现状，T3A 版其余条款继续有效。

## 1. 目标

T3B 页签（key `budget-multi`，标签「T3B 多主体编制套表」，原由 `src/components/ResearchSummaryView.tsx` 以 multi 模式渲染多主体版编制套表原型）
改为**直接显示 `docs/formdocs-multi/*.md` 这批表单文档**，不再使用 ResearchSummaryView 多主体渲染。

- 文档共 **43 篇 = T3A 清单 37 篇 + 6 个多主体专属表单**（BAA.11、BB.4.2.b、BB.4.2.b.1、BJ.C、BJ.C.R、BO.ELIM）；
- 内容一律由 XML 文字源逐字生成（T3A 同款生成链路）：不润色、不改口径、不改表样；
- 页签 key 与标签不变（`budget-multi` / 「T3B 多主体编制套表」）。

## 2. 参照实现（照搬 T3A，不新造轮子）

T3A「表单文档页」（T5 专项方案说明同型做法）已完成的三件套即为本页参照基准：

- 组件 `src/components/FormDocsView.tsx`（左侧目录 + 右侧 ByteMD Viewer 阅览）；
- 数据源 `src/data/pages/formDocsMarkdown.ts`（`import.meta.glob` 打包期内联 Markdown 原始文本）；
- 生成脚本 `scripts/generateT3aFormDocs.ts`（XML 文字源 → 表单文档）。

T3B 照此结构落地，三处对应改动：

1. **组件复用**：`FormDocsView` 参数化——文档集 / 会话记忆键 / 文档源目录经组件参数传入；T3A 与 T3B 为同一组件的两个实例（T3A 不传参，渲染与现状一致），不复制组件。
2. **数据源**：新建 `src/data/pages/formDocsMarkdownMulti.ts` 读 `docs/formdocs-multi/*.md`；与 T3A 数据源共用的解析（标题 / 归组 / 排序）与装配逻辑提取至共享模块（`formDocsShared.ts`），两处共用一份口径，防止漂移。
3. **生成脚本**：`scripts/generateT3aFormDocs.ts` 扩为单文件双范围——缺省（不带 `--scope`）行为与现状一致（仍生成 `docs/formdocs/` 37 篇）；`--scope multi` 生成 43 篇至 `docs/formdocs-multi/`。

## 3. 页面构成

- **左侧目录**：按 BA / BB / BF / BO 归组，条目显示「表单编码 + 表单名」；编码与表单名解析自文档首个 `# 编码 名称` 标题，解析不到时回退文件名。四组篇数 **12/22/5/4**（合计 43），BJ.C、BJ.C.R 归 BF 组（理由见 §6）。
- **右侧正文**：ByteMD Viewer 渲染当前选中文档的 Markdown 全文（GFM），标题、段落、表样按文档原样呈现；底部提供「上一篇 / 下一篇」翻页。
- **默认文档**：进入页签默认打开第一篇；用 sessionStorage 记住当前文档（整页刷新后续显），键 `budgetdemo:t3b-doc:v1`——与 T3A 页签（`budgetdemo:t3a-doc:v1`）各自独立，互不串扰。
- 顶部「Markdown 编辑」按钮在本页保持不可用（只读阅览、无编辑入口），与 T3A 页签一致。

## 4. 渲染与样式（复用 T3A 同款）

- 文档内嵌的 `<style>…</style>` 块在**渲染前剥离**（沿用同一数据源剥离逻辑）；样式统一由应用样式表提供，避免样式块被当正文显示。
- 表格样式沿用 `src/index.css` 的 `.t3a-doc-view` 作用域规则（T3B 正文容器沿用同一类名）：表头深蓝底白字、单元格边框、表样单元格不换行、数值右对齐、表样隔行浅底。**不得**给全局 `table`/`th`/`td` 加样式（会影响其他页签）。
- 宽表横向滚动条常显、可见；应用内用标准横向滚动，不用「滚动条置顶」等翻转技巧。
- 不改名 `.t3a-*` 样式类（避免波及 T3A 既有 37 篇文档与 `index.css`）。
- 深色模式下沿用现状基底，不新增深色适配（与 T3A 表现一致）。

## 5. 明确不做（边界）

- 不改表样 / 字段 / 口径内容：纯转换，内容由 XML 文字源逐字决定。
- 不改 T3A 既有 37 篇内容；不改 T1 / T4 / T5 / T6~T9 任何页签与既有组件；T3A 页签渲染保持现状（组件以缺省参数兼容，T3A 无感）。
- 不提供「在线编辑 / 保存回盘」：这批 Markdown 由生成脚本产出，手改会被覆盖；页面无导出入口。
- 不做导出与打包：不跑 `build` / `build:spa`、不更新 `spa.html`（用户点名时才做）。
- 不装依赖；不删 `ResearchSummaryView.tsx`（T1 总览、T4 基础静态数据仍在使用）。
- 本机无版本控制（无 `.git`），不做任何 git 操作。

## 6. 与 T3A 的差异点（multi 差异集）

差异集来源：`ResearchSummaryView.tsx` 的 prototype 隐藏集（共 9 项，prototype 隐藏、multi 显示）；T3B 按 multi 全量恢复：

1. **表单级恢复 6 个**：BAA.11、BB.4.2.b、BB.4.2.b.1、BJ.C、BJ.C.R、BO.ELIM；
2. **子表级恢复 3 个**：BB.1.2.d、BB.3.1.D、BB.3.3.D——父表单 BB.1.2 / BB.3.1 / BB.3.3 均保留，仅为其恢复表样段与字段分节；
3. **BJ.C 含 5 张子表**（BJ.C.a / BJ.C.e / BJ.C.d / BJ.C.f / BJ.C.g），文档内连排；
4. **BJ.C.R 为口径总说明、无表样**（不生成分录、不填数据，页面亦无表样）：其文档无「① 预算表样」节，属预期；若验收判定可读性不足，补「本表为口径总说明、无表样」说明文字——属内容增删，须先呈报用户确认后执行；
5. **目录归组修正**：BJ.C、BJ.C.R 归 **BF 组**（与页面菜单 BF 组一致：BF.1、BF.3、BF.4、BJ.C、BJ.C.R）。数据源默认按编码前两位字母归组会把 `BJ.*` 落到未知组，T3B 数据源按 `BJ → BF` 修正，不得出现孤立「BJ」组；
6. 与 T3A 重叠的 37 篇内容一致：除 BB.1.2 / BB.3.1 / BB.3.3 的 .d / .D 恢复段外，逐字相同、无其他差异。
