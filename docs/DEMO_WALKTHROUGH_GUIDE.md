# 演示走查指南 (DEMO WALKTHROUGH GUIDE)

> 适用系统：UEADEMO —— 甜甜圈集团全面预算编制演示系统（虚构企业，泛烘焙装备行业）
> 预算年度：2027 ｜ 编制主体：甜甜圈集团公司及 12 家法人层级（JT/A/B/C/D/BA/BB/BC/BD/DA/DB/DC）
> 金额单位：万元/人民币 ｜ 当前生效版本：2027年度正式版 (V2.0，年度合计 32,410 万)
> 演示口径提示：对外讲解一律使用业务中性表述——"保存数据 / 数据备份与维护 / 多维透视分析"，不谈内部技术实现。

## 1. 演示前准备清单

### 1.2 演示前检查项

- [ ] 浏览器：使用 Chrome 或 Edge 最新版本，建议 1920×1080 及以上分辨率，按 F11 全屏演示。
- [ ] 落地页确认：打开系统后默认进入 **BB.1.1 销售合同签约额预算**（需求演示模式），这是演示主线的起点。
- [ ] 模式确认：左侧边栏顶部处于"**需求演示**"模式（绿色高亮）；如需讲规格文档，可切到"**需求说明**"模式。
- [ ] 数据状态：系统自带完整演示数据（合同、订单、投资、报表全链路），开箱即可讲。
- [ ] 数据重置：演示中的编辑会保存在浏览器本地。如上一场演示改动过数据，重置方式为——浏览器"清除站点数据/清除浏览记录中的网站数据"后刷新页面，即可恢复出厂演示数据；或换用浏览器无痕窗口开始新一场演示。
- [ ] 侧边栏宽度：侧边栏支持拖拽调宽（240~520px），演示前拖到能完整显示表名的宽度；双击拖拽手柄可恢复默认。
- [ ] 目录状态：用侧边栏的"全部展开 / 仅一级 / 全部收缩"按钮，把目录树整理成走查所需的展开状态。

## 4. 交互亮点清单

演示中可随时穿插的"惊喜点"，建议每场至少展示 3 个：

1. **在线表格编辑（Luckysheet 工作台）**：类 Excel 的在线编辑体验，双击即改、支持公式，业务人员零学习成本。
2. **公式即时重算**：修改任一月度数，行合计、年度合计、下游汇总表联动刷新，"改一个数、全链路重算"。
3. **Excel 导入导出**：各编制表支持一键导出 Excel 汇报底稿；雇员费用（BA.6）等支持模板化批量导入，存量习惯无缝迁移。
4. **批量分摊**：年度目标数一键按策略拆分到 12 个月（批量分摊弹窗），告别手工逐格填数。
5. **多维透视分析**：BO.4/BO.6/BO.7 三级透视能力——固定汇总→自由交叉→计算工作台，从汇报到即席分析全覆盖。
6. **版本管理与对比**：V1.0 初稿（28,650 万）→ V2.0 正式版（32,410 万）版本留痕，每版记录创建人、时间、审核状态。
7. **单体/合并一键切换**：主体切到"集团合并"即自动应用抵销规则，穿透可查。
8. **侧边栏拖宽 + 目录批量操作**：侧边栏 240–520px 自由拖宽（双击复位）；"全部展开/仅一级/全部收缩"一键整理目录树；顶部搜索框按编号或表名秒定位。
9. **双模式切换**：同一入口在"需求演示"（可操作系统）与"需求说明"（规格文档）间切换，讲方案与看文档不换窗口。
10. **内部交易路径可视化**：合同行上直接展示"集团公司→D公司→外部客户"式的内部交易链路，抵销逻辑一眼看懂。

## 5. Q&A 预案

> 统一话术原则：数据相关问题一律使用"保存数据、数据备份与维护、浏览器本地保存"等业务中性表述。

**Q1：系统能对接我们的 ERP / 总账系统吗？**
建议回答：本系统当前为需求演示环境，重点展示编制模型与业务流程。正式实施时，主数据（组织、科目、客户、合同）与实际数交换都通过标准接口方案对接 ERP，演示中的字典化主数据结构（AA/AB/AM 三类）就是为对接预留的规范底座。

**Q2：数据存在哪里？安全吗？**
建议回答：演示环境的数据保存在您本机浏览器中，不上传任何服务器，关掉浏览器数据也不会丢；正式部署时按贵司要求落在企业内部环境，数据备份与维护纳入统一运维策略。

**Q3：能多人同时协作编制吗？**
建议回答：演示版聚焦单机走查编制模型。正式方案中，各法人、各事业部按权限分工填报，汇总、审核、版本锁定在集团层完成——演示里的 12 家法人主体切换和版本管理，就是多人协作流程的模型基础。

**Q4：三表平衡怎么验证？出了不平怎么办？**
建议回答：BO.3 提供自动勾稽稽核——资产=负债+权益、利润表与现金流量表勾稽项由系统逐条检查并给出结果；不平时可沿"报表项→映射规则（AM.1）→业务编制表"逐层穿透定位到源头数据行，改源头、报表自动重算。

**Q5：预算做完后，实际数怎么对比？能做预实分析吗？**
建议回答：编制模型的月度颗粒（每合同×12 个月）就是为预实对比设计的；正式实施接入实际数后，BO.4/BO.6 的多维透视分析可直接输出预实差异的多维切片。演示环境重点展示编制侧闭环。

**Q6：调整了假设（比如汇率、加成率），已经编好的数会自动更新吗？**
建议回答：静态数据字典（AB.15）与规则（BA.1.1、AM 映射）集中维护、下游引用，调整后相关测算联动刷新；预算编制表不直接维护税率参数。

**Q7：能出我们自己格式的报表吗？领导只看 Excel。**
建议回答：所有编制表和汇总表支持一键导出 Excel，导出即汇报底稿；固定格式的管理报表可在实施阶段按贵司模板定制，多维透视表也可以把切好的视图直接导出。

**Q8：像我们这样十几家法人、上百张表，系统性能撑得住吗？**
建议回答：演示环境用 12 家法人全链路数据完整跑通了"编制→汇总→合并→稽核"闭环；针对大数据量的汇总分析，系统内置专门的多维透视分析计算工作台（BO.7），大表交叉汇总秒级响应。

**Q9：业务人员不懂财务，填错了科目怎么办？**
建议回答：业务人员只填业务表（合同、订单、排产、费用），不直接碰科目——科目翻译由 AM.1 映射规则自动完成；填报界面全部字典下拉选择（合同、客户、产品类别(财)），从源头减少错填。

**Q10：需求演示模式和需求说明模式有什么区别？**
建议回答：需求演示模式是可操作的系统原型，用来走流程、看交互；需求说明模式是同一套功能的规格文档视图，用来逐条确认需求条款。评审会上两个模式随时切换，"看到的"与"写下的"始终一致。

**Q11：预算批下来之后要调整，流程怎么走？**
建议回答：日常口径调整走 BF.4 预算综合调整表——调增调减独立成行、理由留痕、不覆盖业务底稿；重大调整则升级版本（如 V2.0→V3.0），新旧版本并存可比。

**Q12：存量订单转收入的测算逻辑是黑盒吗？**
建议回答：不是。AM.1 存量转收入成本测算映射把转化模型显性化：每笔订单的收入确认方式（验收进度/FAT/SAT/终验一次性）、结转比例、成本率都在表内可见可改，测算结果可回溯到规则。
